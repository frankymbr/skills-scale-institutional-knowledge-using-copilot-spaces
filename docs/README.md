# OctoAcme Project Management Docs README

Welcome to the OctoAcme Project Management documentation! Here you'll find comprehensive guidance on how OctoAcme runs projects, organized by phase and topic. This documentation is designed to help new teammates quickly understand our approach, roles, and key processes.

## OctoAcme Project Management Overview

OctoAcme follows a structured, customer-first approach to project management built on five core principles: prioritizing customer value and usability, delivering small testable increments iteratively, maintaining clear ownership with named Project Managers and Product Leads, making data-informed decisions based on measured impact, and fostering psychological safety to encourage feedback and learning.

Our project lifecycle spans five phases:

1. **Initiation** – Validate business need, align stakeholders, and create a Project One-pager with measurable success metrics
2. **Planning** – Break work into shippable increments, define acceptance criteria and Definition of Done, identify dependencies and risks
3. **Execution** – Build, test, and review code through daily standups, weekly syncs, and sprint-based iterations using GitHub Projects
4. **Release** – Deploy, verify functionality, and announce updates to stakeholders
5. **Close & Retrospective** – Capture learnings and identify action items for continuous improvement

Our organization is built on four core personas with distinct responsibilities: **Project Managers** coordinate delivery, manage schedules and risks, and maintain transparency; **Product Managers** define what to build to maximize customer value and prioritize backlogs; **Developers** implement features, collaborate on design, and identify technical risks; and **QA/Testing** validates quality and acceptance criteria. Clear ownership and collaboration across these roles is essential to our success.

Communication and risk management are formalized through structured cadences: weekly syncs between PM and Product Manager, twice-weekly team standups, and monthly stakeholder updates. We maintain a Risk Register throughout each project, assess risks for impact and likelihood, and follow clear escalation paths from team level to PM to Product Lead to Sponsor. Quality is embedded throughout execution via automated CI/CD pipelines, code review requirements, comprehensive testing (unit, integration, and end-to-end), and security scanning.

## Key Principles

- **Customer-first** – Prioritize customer value and usability
- **Iterative delivery** – Deliver small, testable increments
- **Clear ownership** – Each project has named Project Manager and Product Lead
- **Data-informed decisions** – Measure impact and iterate based on evidence
- **Psychological safety** – Encourage feedback and learning
